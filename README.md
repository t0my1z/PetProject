Summary:
 
The capabalities of this program are gonna be the following:
 
* Based on a .yaml file used for configuration, we will be able to open sockets in both udp or tcp. You will be able to configure the type of conexion(udp or tcp), the protocol (custom udp or tcp), the endianess (big or little) of the data, the host, the localport, the remoteport, the frequency and the size of the incoming and outgoing buffers.
 
* There will be a custom protocol for both udp and tcp
 
* We will have a .idl file in which the data structures and available messages will be defined in a format that fits the custom udp and tcp protocols. There should only we one .idl file for both udp and tcp protocols.
 

We will use the following:

* We will use C++ 23 for this program, since we want the logging functionality present in there

* CMake and ninja as build systems

* Standalone Asio to abstract platform dependent code for sockets

* yaml-cpp for configuration files

## Building in VS Code on Windows

The current presets use MSYS2 UCRT64 GCC in `C:\msys64\ucrt64\bin`
and the native Windows CMake and Ninja bundled with Visual Studio 2022
Build Tools. The workspace settings enable CMake Tools preset mode.
Do not substitute MSYS2's `usr\bin\ninja.exe`: its POSIX shell cannot
interpret the Windows compiler commands generated by native CMake.

1. Install the VS Code CMake Tools extension and the tools at the paths above.
2. Run **CMake: Select Configure Preset** and choose **Debug Build** or
   **Release Build**.
3. Run **CMake: Select Build Preset** and choose **Debug** or **Release**,
   matching the configure preset.
4. Run **CMake: Build**.

When switching from an MSYS build, run **CMake: Delete Cache and Reconfigure**
after selecting the preset so cached compiler and generator paths are not reused.

The architecture will be:

* A static library that exposes an API for UDP and TCP sockets using the Asio library and expects a .yaml file with a configuration and lets you manage the reading and writing of those sockets, as well as exposing the buffers with the info they send/receive. Should be completely platform independent and work in both windows and linux.

* A static library that defines a tcp and udp custom protocol, and has the decoding and encoding needed for said protocols.

* An executable that will use the static lib for socket management, and the static lib of custom protocols, to communicate using a .idl file in which the messages and data structures that will be sent through the sockets will be defined. This executable will need to be able to load dynamic libraries called modules, that through configuration will be able to access the buffer opened by the socket assigned to that module. The interface for modules will be defined in this executable, and exposed to each module via header files.

* A module will be a small dynamic library that will be linked on runtime by the executable via config. It will implement the interface exposed by the executable. This interface will have a read and write method, in which the module will be able to interact with the buffer exposed by the socket.
